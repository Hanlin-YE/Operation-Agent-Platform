# 内部销售流程

## 修改范围

本分支基于上游提交 `a6d0ca9`，只调整销售日常流程。内容、论文研究、市场、图谱与培训代码保留，入口统一移到实验区并显示封存提示。封存指暂停继续扩展，已有页面和接口仍可访问。

## 日常操作

1. 打开首页，查看逾期和今天到期的任务。无日期的任务单独显示，未来日期的任务可在客户详情查看。
2. 从「线索管理」进入客户详情。点击「编辑线索」修改公司、联系人、联系方式、来源、标签或备注，点击保存。关闭编辑框或按 Escape 可取消本次修改。
3. 点击「规则评分」。评分及解释均由现有规则生成；客户资料变更后会提示重新评分。
4. 选择渠道并生成话术，审核后直接在文本框修改。「保存话术」更新当前话术；「保存为跟进任务」先保存当前修改，再将相同内容加入该客户的待跟进任务。
5. 用「跟进任务」表单记录行动内容与下次时间，时间按北京时间输入。完成任务后点击「完成」，也可在首页点击「标记完成」。已完成任务会从首页待办中移除，历史记录保留。

## 参数承诺检查

- 系统提示要求模型先询问工况、目标参数和验证方法，不得对客户承诺性能与交付安排。
- 生成结果在写入前检查；手工编辑保存和话术转跟进任务同样检查。检查失败返回 HTTP 422，界面显示原因。
- 保守拦截保证措辞、带单位的量化数值及期限、百分比和部分性能数值句式。带数值的问题也可能被拦截，此时改为询问目标参数，不在话术中直接写数值。
- 已有历史话术打开后也会检查，需修改通过后才能保存或转跟进。内部跟进备注用于记录实际沟通，不作为客户话术检查。
- 未配置模型或模型未返回内容时，使用明确标识的本地询问模板。被检查拦截的模型输出不保存。
- 该机制不构成事实核验，不能覆盖所有措辞，仍需销售与技术人员审核。

## 本地保存与验证

默认写入 `data/app-data.json`，重启保留记录。`DEMO_EPHEMERAL_STORE=true` 与 Cloudflare 模式会改用内存数据，只用于演示。仓库自带的初始线索属于示例数据。

本次没有处理数据库迁移、用户认证、多人并发写入或外部采集接入。本地文件在并发写入时仍可能发生覆盖，使用范围应限制在单机顺序操作。

执行 `npm run test:sales` 可检查线索字段保存、模型输出拦截、话术修改后转跟进、任务完成，以及北京时间跨天的待办归类。接口回归使用内存数据，持久化回归在临时目录验证独立进程读取，不修改本地客户文件。

完整安装、使用、备份恢复和维护说明见 [PDF 手册](manual/sales-workbench-manual.pdf) 与 [TeX 源文件](manual/sales-workbench-manual.tex)。
