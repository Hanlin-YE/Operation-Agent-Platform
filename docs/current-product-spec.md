# 自超滑电机 AIGC 销售 Agent - 当前产品规格与实现审阅

更新时间：2026-07-13

## 1. 审阅结论

当前仓库是一个可运行的 **P0 演示原型**，不是已完成的生产级 AIGC 销售 Agent。

它已经打通了最小闭环：

```text
新建线索
-> 打开线索详情
-> 规则评分
-> 从产品/知识文本中做关键词匹配
-> 生成 6 类销售话术
-> 保存到线索时间线
```

它尚未实现当前 PRD 和研究文档中最关键的自超滑产品能力：

```text
自超滑电机应用推荐
场景问诊
真实 RAG
文献/官网来源管理
Review Agent
批量拓客与 CSV 导入
公司与联系人实体建模
外部线索发现
```

## 3. 当前 Agent 实现边界

### 3.1 潜客评分 Agent

已实现规则：

- 行业关键词匹配
- 应用场景关键词匹配
- 公司规模粗略判断
- 联系人职位关键词判断
- 紧迫度关键词判断
- 贸易商、低价、比价等风险关键词扣分

输出：

- 0-100 总分
- A/B/C/D 等级
- 六个分项分数
- 固定模板化解释
- 推荐下一步动作

限制：

- 不是 LLM 评分，也不是训练过的 ML 模型。
- 没有 account/contact 双层评分。
- 没有批量排序、反馈学习、评分规则配置、评分版本回放页面。
- 现有行业词典仍偏通用工业电机，未接入清力/FrictionX 的自超滑业务词表。

### 3.2 话术生成 Agent

已实现：

- 电话开场白
- 微信首次触达
- 邮件开发信
- 报价后跟进
- 价格异议处理
- 技术参数确认

实现方式：

1. 根据线索文本，从产品和知识条目中做字符串关键词排序。
2. 取前 2 个产品和前 3 条知识作为上下文。
3. 若配置 `OPENAI_API_KEY`，调用 OpenAI-compatible Chat Completions API。
4. 没有 API Key 时，使用本地固定模板生成话术。

限制：

- 当前不是向量 RAG，没有 embedding、chunk、hybrid retrieval 或 rerank。
- 引用标签只是“产品名称/知识标题”，没有可追溯 source、页码、原文片段或可信度。
- UI 中的生成内容不可编辑，和 PRD 的“可编辑正文”不一致。
- 话术未接入自超滑电机产品推荐、场景问诊和性能承诺拦截。
- 没有 Review Agent；没有事实、性能数字、语气或合规审查。

### 3.3 产品与知识匹配

已实现：

- 以线索的公司名、行业、标签、备注为 query。
- 将 query 按标点和空格切词。
- 用词是否出现在产品/知识文本中的次数排序。

限制：

- 不是知识型推荐、约束型推荐或会话式推荐。
- 没有转速、负载、接触循环、温升、空间尺寸、摩擦痛点、证据需求等自超滑选型约束。
- 没有缺失信息、问诊问题、推荐理由或“是否适合样品测试/联合验证”输出。

## 4. 前端中可见但尚未具备对应功能的部分

| 页面/面板 | 用户预期 | 当前状态 | 原因 |
| --- | --- | --- | --- |
| Agent Studio 的 “Lead Context / Scoring / RAG / Pitch” 流程 | 可配置、可调试、可看节点输入输出 | 仅文案展示 | 没有 Agent graph、trace、配置或运行记录模型 |
| Dashboard 的 “今日优先动作” | 可一键进入待办或处理队列 | 仅说明文字 | 没有任务队列、待办筛选或 Follow-ups 页面 |
| Dashboard 的指标 | 可点击钻取相关线索/话术/跟进 | 只显示数值 | 没有 drill-down 路由与筛选状态 |
| 产品库 | 管理自超滑电机产品/应用 | 只有通用电机 demo 数据 | 没有应用方向、部件、摩擦痛点、验证方式等字段 |
| 知识库 | 上传论文、官网、产品手册并进行 RAG | 只可粘贴文本 | 没有上传、解析、chunk、embedding、source registry |
| 评分面板 | AI 动态评分与证据解释 | 固定规则评分 | 没有模型、外部数据、证据链或配置界面 |
| 话术面板 | 可编辑、可审查、可引用证据 | 生成后仅展示和保存 | 没有编辑器、Review Agent、citation detail 或版本控制 |

## 7. 当前技术架构 - As Built

```text
Next.js App Router
  -> Route Handlers
    -> Agent / Scoring / Retrieval services
      -> Repository functions
        -> data/app-data.json
```

实际技术组成：

- Next.js 14 + React 18 + TypeScript
- 文件型 JSON 数据存储
- Next.js Route Handlers
- 可选 OpenAI-compatible API
- 本地模板 fallback
- lucide-react 图标

明确未采用：

- PostgreSQL
- Prisma
- pgvector / Qdrant / Milvus
- Redis / 队列
- 对象存储
- 身份认证/RBAC
- 文件上传服务
- 自动化测试框架

## 8. 推荐的审阅决策

### 已批准决策（2026-07-13）

| 决策 | 审核结论 | 对实现的约束 |
| --- | --- | --- |
| 首要产品主线 | 已批准：自超滑空心杯电机 | 首批数据模型、推荐规则、话术和知识库围绕空心杯有刷电机 / 微驱动构建 |
| 对外宣传主线 | 已批准：自超滑空心杯电机 | 页面、话术、案例和内容资产不再以泛工业电机为主语 |
| 产品资料来源 | 待用户上传 | 上传后进入 Source Registry、RAG 与 Review 流程；不得直接当作已核验性能结论 |
| 内容审核 | 已批准：先 Review，再人工确认 | 对外话术、性能表述、公司事实和案例不得绕过审核 |
| 社会效益表述 | 已批准：纳入价值叙事 | 必须区分可证实设备指标、可推导运营价值和待验证社会效益 |

### 必须批准后才应继续开发的范围

1. **产品定位**：已确认首个主线为“自超滑空心杯有刷电机 / 微驱动”，不再以泛工业电机作为首要场景。
2. **数据层**：确认从 JSON demo store 迁移至 PostgreSQL + Prisma，或先采用 SQLite 作为过渡。
3. **RAG 范围**：确认 P0.5 是否只做本地资料上传和引用，还是包含官方网站 URL 抽取。
4. **Review 边界**：确认任何性能数字、公司主体事实和对外话术是否都必须人工批准。
5. **外部拓客边界**：确认是否只生成草稿和线索，明确不自动群发。

### 建议的下一开发批次

```text
P0.5-A 数据模型：Source / Document / Chunk / ProductApplication / Recommendation / Review
P0.5-B 前端：Companies、Follow-ups、Review Queue、评分规则设置
P0.5-C 自超滑推荐：约束匹配 + 场景问诊 + 证据缺口
P0.5-D RAG：文档上传、解析、检索、来源引用
```
